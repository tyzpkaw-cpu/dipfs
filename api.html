API reference

Everything is exported from dipfs.js. The data under data/ is loaded lazily and cached; you never have to think about it.

Loading the module

// Browser — data/ is resolved relative to the module itself
import { decompose } from 'https://dipfs.js.org/dipfs.js';

// Node.js (18+) — keep dipfs.js and data/ together
import { decompose } from './dipfs.js';

No configuration and no dependencies. In Node the module reads the data with node:fs; in the browser it uses fetch.

Functions

FunctionResult
decompose(text)Promise<(Record | null)[]> — one entry per code point, in order. Characters outside the dataset (Latin letters, spaces, emoji, rare hanzi) are null.
lookup(char)Promise<Record | null> — a single character. Throws TypeError for anything longer than one code point.
charsWith(part)Promise<string[]> — every character that lists part among its parts; [] for an unknown part. Whole-character entries are not indexed.
preload(text)Promise<number> — fetch the chunks covering text ahead of time; resolves to the number of chunks actually fetched.
stats()Promise<Meta> — dataset metadata: counts, structure distribution, chunk table.
structureInfo(code){ code, zh, en } | null — the five structure classes.
loadAll()Promise<number> — load every chunk (handy in Node or for offline use); resolves to the character count.

Record

{
  char: '好',
  structure: { code: 'z', zh: '左右', en: 'left–right' },
  parts: [
    { glyph: '女', reading: 'nǚ', key: 'n', whole: false,
      names: [ { name: '女', reading: 'nǚ', key: 'n' } ] },
    { glyph: '子', reading: 'zi', key: 'z', whole: false,
      names: [ { name: '子', reading: 'zi', key: 'z' } ] }
  ],
  traditional: []          // [ '這' ] for 这, [ '發', '髮' ] for 发
}
  • names — a part can carry several names: 辶 is 走 or 走之; 亠 is 亠, 头 or 玄字头. The part-level reading and key come from the first name.
  • key — the key letter the source IME uses for the part, taken from the name's reading (提手 → t, 宝盖 → b).
  • whole — true for the first part of standalone characters: the character itself, named 整字 (“whole character”). For 一 the first part is 一, followed by its strokes.
  • Records are cached and reused between calls; treat them as read-only.

Data format

FileContents
data/meta.jsoncounts, structure distribution, and the chunk table (each chunk's file name and first/last code point)
data/chars-NN.json16 chunks of 512 characters, sorted by code point. Each record is [char, structure, parts, traditional?], with parts as [[glyph, [[name, reading, key], …]], …]
data/parts.jsonreverse index: { "氵": "汉江河海…" }

Rebuild the JSON from the source table with python3 tools/build-data.py. To self-host, copy dipfs.js and the data/ directory together.
